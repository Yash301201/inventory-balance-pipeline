# Scenario fixture and labels

Run the deterministic fixture generator from the project root:

```sh
python src/generate_sample.py --rows 1000 --seed 42 --output work/clean.csv --scenario-output data/ground_truth/scenario_transactions.csv
```

The scenario CSV is pipeline input. Its companion `scenario_transactions.labels.csv`, `scenario_transactions.expected_balances.csv`, and `scenario_transactions.manifest.json` are ground truth only; do not pass them to the pipeline as input.

- `source_record` is the one-based logical data-record ordinal in the scenario input; the header is excluded.
- `scenario_id` identifies the case being exercised.
- `expected_disposition` is `accepted_active`, `accepted_superseded`, or `rejected`.
- `expected_reason_code` is populated for rejected records.
- The expected balance CSV is hand-calculated from the documented events, not generated by the pipeline under test.
- The manifest records input, labels, and expected-output hashes plus scenario and disposition counts.
- Labels and expected answers never appear in the pipeline input.

Cases include an audited correction from receipt 10 to receipt 8, a subsequent issue of 3, an identical redelivery, a conflicting ID, an unknown product, a missing location, an invalid quantity, an invalid date, and signed adjustments. The fixture also contains dates without movement so carry-forward balances can be checked.

For the correction example, the expected location balance is 8 at the end of Jan 1 and 5 at the end of Jan 2. The original receipt version remains visible as superseded. Reprocessing the same input must leave those business balances unchanged.
